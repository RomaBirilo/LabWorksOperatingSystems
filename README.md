## Лабораторная работа №1

### Тема: Создание процессов

**Задача:** написать консольную программу `Main` и две утилиты (служебные программы) `Creator` и `Reporter`.

### Функционал программы Main

Программа `Main` выполняет следующие действия:

1. Запрашивает с консоли имя бинарного файла и количество записей в этом файле.
2. Запускает утилиту `Creator`, передавая через командную строку имя создаваемого бинарного файла и количество записей.
3. Ожидает завершения работы утилиты `Creator`.
4. Выводит содержимое созданного бинарного файла на консоль.
5. Запрашивает с консоли имя файла отчета и оплату за час работы.
6. Запускает утилиту `Reporter`, передавая через командную строку:

   * имя исходного бинарного файла,
   * имя файла отчета,
   * оплату за час работы.
7. Ожидает завершения работы утилиты `Reporter`.
8. Выводит отчет на консоль.
9. Завершает свою работу.

### Утилита Creator

Утилита `Creator` выполняет следующие действия:

* Создает бинарный файл, имя которого и количество записей получает через командную строку.
* Записи файла вводятся с консоли и имеют следующую структуру:

```
struct employee
{
    int num;        // идентификационный номер сотрудника
    char name[10];  // имя сотрудника
    double hours;   // количество отработанных часов
};
```

### Утилита Reporter

Утилита `Reporter` выполняет следующие действия:

* Создает текстовый файл, содержащий упорядоченный список сотрудников с начисленной заработной платой.
* Получает через командную строку:

  * имя исходного бинарного файла,
  * имя файла отчета,
  * оплату за час работы.
* Отчет содержит:

  * заголовок,
  * строку с названиями столбцов,
  * список сотрудников с расчетом зарплаты как произведение отработанных часов на оплату за час.

**Примечание:** для ожидания завершения работы процессов `Creator` и `Reporter` используется функция `WaitForSingleObject(INFINITE)`.

## Лабораторная работа №2

### Тема: Создание потоков

**Задача:** написать программу для консольного процесса, который состоит из трех потоков: `main`, `min_max` и `average`.

### Поток main

Поток `main` выполняет следующие действия:

1. Создает массив целых чисел, размерность и элементы которого вводятся с консоли.
2. Создает потоки `min_max` и `average`.
3. Дожидается завершения потоков `min_max` и `average`.
4. Заменяет максимальный и минимальный элементы массива на среднее значение элементов массива.
5. Выводит полученные результаты на консоль.
6. Завершает работу.

### Поток min_max

Поток `min_max` выполняет следующие действия:

* Находит минимальный и максимальный элементы массива и выводит их на консоль.
* После каждого сравнения элементов приостанавливает выполнение на 7 миллисекунд.
* Завершает свою работу.

### Поток average

Поток `average` выполняет следующие действия:

* Находит среднее арифметическое значение элементов массива и выводит его на консоль.
* После каждой операции суммирования элементов приостанавливает выполнение на 12 миллисекунд.
* Завершает свою работу.

**Примечания:**

* Для ожидания завершения работы потоков используется `WaitForSingleObject(INFINITE)`.
* Для приостановки выполнения используется функция `Sleep`.

## Лабораторная работа №3

### Тема: Синхронизация потоков при помощи критических секций и событий. Обработка тупиков

**Задача:** написать программу для консольного процесса, который состоит из потока `main` и нескольких экземпляров потока `marker`.

### Поток main

Поток `main` выполняет следующие действия:

1. Выделяет память под массив целых чисел, размерность которого вводится с консоли.
2. Инициализирует элементы массива нулями.
3. Запрашивает количество потоков `marker`.
4. Запускает заданное количество экземпляров потока `marker`, передавая каждому его порядковый номер.
5. Подает сигнал на начало работы всех потоков `marker`.
6. Циклически:

   * ожидает, пока все потоки `marker` не подадут сигнал о невозможности продолжения работы;
   * выводит содержимое массива на консоль;
   * запрашивает номер потока `marker` для завершения;
   * подает выбранному потоку сигнал на завершение;
   * ожидает завершения этого потока;
   * выводит содержимое массива;
   * подает сигнал на продолжение работы оставшимся потокам.
7. Завершает работу после завершения всех потоков `marker`.

### Поток marker

Поток `marker` выполняет следующие действия:

* Начинает работу по сигналу от потока `main`.
* Инициализирует генератор случайных чисел своим порядковым номером.
* Работает циклически:

  * генерирует случайное число и вычисляет индекс массива;
  * если элемент равен `0`, приостанавливается на 5 мс, записывает свой номер в элемент, снова приостанавливается на 5 мс и продолжает цикл;
  * если элемент не равен `0`, выводит свой номер, количество помеченных элементов и индекс элемента, который невозможно пометить, подает сигнал потоку `main` и ожидает ответный сигнал.
* При сигнале на завершение заполняет нулями все помеченные элементы и завершает работу.
* При сигнале на продолжение возобновляет цикл.

## Лабораторная работа №4

### Тема: Синхронизация процессов

**Задача:** написать программу для передачи сообщений между процессами через общий файл. Программа включает один процесс `Receiver` и несколько процессов `Sender`.

### Процесс Receiver

Процесс `Receiver` выполняет следующие действия:

1. Вводит имя бинарного файла и количество записей.
2. Создает бинарный файл для сообщений (максимальная длина сообщения 20 символов).
3. Вводит количество процессов `Sender`.
4. Запускает процессы `Sender`, передавая имя файла сообщений.
5. Ожидает сигналы о готовности от всех процессов `Sender`.
6. Циклически по команде с консоли читает сообщение из файла или завершает работу.

### Процесс Sender

Процесс `Sender` выполняет следующие действия:

* Открывает файл сообщений (имя получает из командной строки).
* Отправляет процессу `Receiver` сигнал о готовности.
* Циклически отправляет сообщение или завершает работу. Текст сообщения вводится с консоли (длина менее 20 символов).

**Дополнительные требования:** передача сообщений организована как кольцевая очередь FIFO.

## Лабораторная работа №5

### Тема: Обмен данными по именованным каналам

**Задача:** написать программу для управления доступом параллельных процессов к файлу по именованным каналам.

### Процесс Server

Процесс-сервер выполняет следующие действия:

1. Создает бинарный файл с записями структуры `employee`.

```
struct employee
{
    int num;        // идентификационный номер сотрудника
    char name[10];  // имя сотрудника
    double hours;   // количество отработанных часов
};
```

2. Выводит созданный файл на консоль.
3. Запускает процессы-клиенты `Client`.
4. Обслуживает запросы клиентов:

   * при модификации записи доступ блокируется для других клиентов;
   * при чтении записи блокируется только доступ к этой записи.
5. После завершения всех клиентов выводит модифицированный файл.
6. По команде с консоли завершает работу.

### Процесс Client

Процесс-клиент выполняет следующие действия:

* Циклически запрашивает операцию: модификация записи, чтение записи или выход.
* Доступ к записям осуществляется по ключу (ID сотрудника).

**Модификация записи:**

1. Запрос ключа записи.
2. Отправка запроса серверу.
3. Вывод записи.
4. Ввод новых значений полей.
5. Отправка измененной записи серверу.
6. Завершение доступа.

**Чтение записи:**

1. Запрос ключа.
2. Отправка запроса серверу.
3. Вывод записи.
4. Завершение доступа.
